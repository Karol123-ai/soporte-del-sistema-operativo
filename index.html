01

Introducción y metodología

Objetivo

Explicar las funciones de soporte que el SO ofrece a programas y usuarios, con simuladores para comprobar los conceptos.

Criterios

Gestión de memoria, planificación, relación hardware-software y tendencias actuales (virtualización, contenedores, cloud OS).

Fuentes

Documentación oficial (Linux, Docker, Kubernetes, KVM) y texto de referencia de Silberschatz et al.

Alcance

Los simuladores son didácticos y simplificados; un SO real usa optimizaciones que aquí no se modelan.

02

Evolución del soporte del SO

1960s

Multiprogramación y memoria virtual

Los sistemas de tiempo compartido y la paginación permiten ejecutar varios programas a la vez.

1970–90

UNIX, GUI y sistemas personales

Se consolidan el kernel, los procesos y los sistemas de archivos jerárquicos.

2001–2008

Virtualización x86

VMware, Xen y KVM aprovechan las extensiones de virtualización del hardware.

2013–2015

Contenedores

Docker populariza namespaces y cgroups de Linux; Kubernetes orquesta contenedores.

2020–2026

Cloud, serverless y edge

El SO se abstrae: microVMs, sistemas mínimos para contenedores y cómputo en el borde.

03

Relación hardware-software

El SO es la capa intermedia: oculta la complejidad del hardware y ofrece a las aplicaciones una interfaz uniforme (llamadas al sistema).

Modo usuario / kernel

La CPU restringe instrucciones privilegiadas al kernel.

Llamadas al sistema

Puerta controlada de la aplicación al kernel.

Interrupciones

El hardware avisa eventos (teclado, disco, timer).

Drivers y DMA

Controladores que traducen y mueven datos sin usar la CPU.

MMU y TLB

Traducen direcciones virtuales a físicas.

Timer

Permite el quantum y la expropiación de CPU.

04

Gestión de memoria

Paginación

Divide la memoria en marcos y el proceso en páginas de igual tamaño; evita la fragmentación externa.

Memoria virtual

Permite ejecutar procesos mayores que la RAM cargando páginas bajo demanda.

Fallo de página

Ocurre cuando la página no está en RAM; el SO la trae del disco y puede reemplazar otra.

Reemplazo

FIFO, LRU y Óptimo deciden qué página sale.

05

Planificación (scheduling)

El planificador elige qué proceso listo usa la CPU. Se mide con tiempo de espera, tiempo de retorno y uso de CPU.

06

Avances: virtualización, contenedores y cloud OS

Izquierda: máquinas virtuales, cada una con su propio SO invitado sobre un hipervisor. Derecha: contenedores que comparten el kernel del host.

Virtualización

El hipervisor (KVM, Xen, Hyper-V) reparte CPU, memoria y E/S entre VMs aisladas con apoyo del hardware (Intel VT-x, AMD-V).


Contenedores

Usan namespaces y cgroups para aislar procesos: arranque en segundos y menor consumo que una VM.


Cloud OS

Plataformas que gestionan miles de nodos como un solo sistema (Kubernetes, OpenStack), además de serverless y microVMs.

07

Análisis y conclusiones

Abstracción

Cada avance añade una capa que oculta detalles del hardware.

Equilibrio

No hay algoritmo perfecto: FCFS es simple, SJF minimiza espera, RR favorece la interactividad.

Eficiencia

Memoria virtual y contenedores aprovechan mejor los recursos físicos.

Tendencia

El SO se orienta a la nube: aislamiento, orquestación y escalado automático.

Limitaciones: los simuladores no consideran costos reales de cambio de contexto, TLB ni prioridades. Óptimo (Belady) es solo una referencia teórica.
Uso de IA: se usó IA generativa como apoyo en estructura, código y redacción. El equipo debe revisar y adaptar el contenido antes de entregarlo.
